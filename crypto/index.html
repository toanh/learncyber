Step 3 · Digest

Classroom activity

Symmetric — one shared secret

  1. One partner generates a key and emails it to the other.
  2. Sender: type a message, paste the key, press Encrypt. Email the output.
  3. Receiver: paste the ciphertext as input, paste the same key, press Decrypt.
  4. Swap roles and repeat. The key never changes — only which box you fill.

The point of this half: that key travelled by email. Anyone who read the email — the school's mail server, an admin, someone at the next desk — can now read every message. Ask the class how you would fix this. That question is the reason the next tab exists.

Asymmetric — two keys, only one is secret

  1. Everyone generates a key pair and emails their public key to the class. Private keys stay on the machine.
  2. To write to Priya, paste Priya's public key into "Key to use", type your message, press Encrypt. Email the output to her.
  3. Priya pastes the ciphertext as input, pastes her own private key, presses Decrypt.
  4. Now try to break it: take a message meant for someone else and attempt to decrypt it with your private key. It fails.

The trap to watch for: students encrypt with their own public key instead of the recipient's. It appears to work, and then nobody but them can open it. You encrypt with the key belonging to the person you are writing to.

Hashing — a one-way fingerprint

  1. Type your name and watch the digest appear. Now change a single letter. Nearly every character of the hash changes — that is the avalanche effect.
  2. Two students type the exact same word. Compare SHA-256 digests: identical. The same input always gives the same fingerprint.
  3. Tick every algorithm at once. Same input, different lengths — MD5 gives 32 hex characters, SHA-512 gives 128.
  4. Switch to File and hash a document. Change one byte of it, hash again: a completely different digest. This is how downloads are checked for tampering.
  5. Now add a salt. Same password, different salt, different digest — which is why a stolen password database with salts cannot be cracked all at once.

The point of this tab: there is no Decrypt button here, and that is not an oversight. A hash cannot be reversed. Sites store the hash of your password, not the password — so try hashing password123 and ask why attackers keep a pre-built list of common digests.

Two things worth asking

  1. Encrypt the same words twice with RSA. The ciphertext differs each time. Why would that be a good thing?
  2. Try a long RSA message. It refuses past 190 bytes — which is why real systems use RSA to encrypt an AES key, then use AES for the message itself.
