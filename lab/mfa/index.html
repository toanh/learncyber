Stage 1, revisited — now with MFA on

In the lab, guest / guest was enough to get a foothold. Turn MFA on and the guessable password is no longer sufficient: the attacker also needs the current code, which they can't produce without the seed sitting on the enrolled device. Try it — the password alone now fails, and only the live code lets you in.
The bridge back to the lab: the one-way property you learned for signing is the same property doing the work here. Past codes never reveal the seed and never predict the next code, because a hash can't be run backwards. That's why MFA breaks the very first link in the lab's kill chain — knowing the password stops being enough.
Real implementation, not a mock. HMAC-SHA1 runs in your browser via the Web Crypto API and matches the official RFC 6238 test vectors. The seed here is generated client-side and never leaves the page.
